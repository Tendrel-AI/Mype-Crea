## Gaps found and closed in this branch

- G1. No request-time guard stopped an OpenRouter slug from reaching the Anthropic API (or a
  `claude-*` ID from reaching OpenRouter) when a caller bypassed provider construction, for
  example an explicit `model` in a direct request. Both clients now reject a model ID of the
  wrong shape before any network I/O.
- G2. A text-only request to Claude Haiku 5.5 (e.g. a Haiku responder override or the cheap eval
  profile) ran adaptive thinking by default, so thinking could consume the output cap and add
  cost. Text-only Haiku 5.5 requests now send `thinking: {type: "disabled"}`; tool requests keep
  the documented default. Sonnet 5.5 keeps `between_tools`.
- G3. Missing tests: thinking blocks in Anthropic responses, multiple `tool_use` blocks, the
  Anthropic-mode judge request (Haiku, no `temperature`), and the model-shape guards. Added.

## Open items (not changed; need owner decision or other owners)

- C1. Superseded by KAN-70 (owner-approved): the chat path runs through `AiConfigRuntime`, which
  uses the active release's pinned profiles, not `LLM_PROVIDER`
  (`provider-registry.ts:43-47`). `LLM_PROVIDER` selects the primary profile only when a
  baseline draft is created (`baseline.ts:104-135`), and that baseline configures one
  cross-provider fallback per purpose on unavailability, rate limiting, or a missing model, recorded with a durable notice. KAN-69's
  "restart switches every call" and "no automatic provider fallback" therefore hold only for
  direct `getProvider()` callers (evals, judge). The Jira text of KAN-69 should be reconciled
  with the KAN-70 decision.
- G4. `llm_calls` lacks `provider` and `purpose` columns. Closing this needs a migration and a
  repo change (`migrations/`, `src/repos/llm-calls.ts`), outside this branch's scope. The
  logger's provider fallback (`llm-logger.ts:45`) also reads `LLM_PROVIDER` directly; all
  current callers pass `provider` explicitly.
- The direct Anthropic provider silently drops `temperature` (by design, since the 5.5 models
  reject non-default values); the KAN-70 registry instead requires `temperature: 1` for
  Anthropic profiles. The direct path is used by evals only.
- The Anthropic transport is raw `fetch` against the Messages API rather than the official
  `@anthropic-ai/sdk`. It works and is tested with mocked `fetch`; switching to the SDK would add
  a dependency and is a separate decision.
- CI's unit job excludes `evals/**`, so `evals/_support` and `evals/evaluators` tests run only
  locally. The new eval profile mapping lives in `src/services/llm/eval-model-profile.ts` so its
  test runs in CI.
